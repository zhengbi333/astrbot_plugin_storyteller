# alpha-0.272

## 自我纠正：我把清单写死了，违背了我们自己的原则

上一版（0.270）我加了：

```python
_GROUP_BLOCKED_TOOLS = frozenset({"toolbox_fs_write", ... 13 项 ...})
```

**这违背了两条我们自己的原则**：

1. **一切开关在 `_conf_schema.json` 里，面板可改** —— 我们连「工具白名单」都是配置项，我却把新清单写死；
2. **不写死词表** —— 这跟当初 `_SEARCH_INTENT_RE` / `detect_image_intent` 犯的是同一类错。

## 改法（行为不变，但可配）

新增配置项 `capabilities.group_blocked_tools`（字符串，逗号分隔）：

- **默认值 = 原来那 13 项** → **默认行为与 0.270 完全一致**，你不需要动；
- 面板可改、可清空、可加自己装的工具；
- 代码里只保留 `_GROUP_BLOCKED_DEFAULT` 作为**配置缺失时的兜底**，不再是唯一真相；
- 新增 `_group_blocked_tools()` 读配置，**并把它进缓存键**（改配置立即生效，不用等 20 秒 TTL）。

## 为什么不索性默认空

因为默认空 = 群聊能写文件 = 安全回归。
默认保留这 13 项，是**安全的默认值**，和"可配置"不冲突。

## 验证（`audit_87` 26/26，比上一版多 3 条）

- **A0**：`_GROUP_BLOCKED_DEFAULT` 正好 13 项；
- **A4**：配置成 `toolbox_python,toolbox_shell_run` → 清单就是这两项（**覆盖生效**）；
- **A5**：`group_blocked_tools_fallback=false` 且不配 → 清单为空（**可完全关掉**）；
- 其余 23 条（清单内容、is_group 判定、群聊过滤、缓存不串、执行侧硬拦）保持不变。

## 这次纠正的教训

我在"修一个安全漏洞"时，顺手引入了一个**风格漏洞**。
以后每加一个判断/清单，先问一句：**这东西该不该在配置里？** 该在配置里的，就不要写进代码。
