# alpha-0.206

## 第 1 轮迭代：提示词预算体检 + 砍掉最大的一处重复

### 诊断（用你的真实配置 + 真实数据只读快照实测，不靠猜）

测量「一轮接管回复」的实际开销，结论：

| 项 | 实测 |
|---|---|
| 一轮模型调用 | **3 次**（生成 → 润色 → 判定；表情包判定/工具轮次会再 +1~2） |
| 生成用 system | **3702 字 ≈ 2314 tokens** |
| **最大占用** | **`【你可以主动做的事】2059 字 = system 的 55.6%** ← 能力清单声明 |
| 其余分段 | 说话风格 341、身份 216、防认错 195、穿搭 187、思绪指令 166、见闻 128… |

**问题**：你的配置是 `native_tools=True`（原生工具生效）——**工具清单本来就随请求一起发给模型了**，
system 里再塞一份 2059 字的完整清单（含每个能力的参数与示例）纯属重复：既抢模型注意力（影响回复质量），
每轮又白花约 1200 tokens。

### 修复

- `build_declaration(plugin, mode, *, brief=False)`：新增 `brief` 模式——原生工具生效时只给**一句提示**
  （"需要真的做点什么时直接调用对应工具…只有工具返回成功才算做到了"），不再罗列清单；
- `main` 侧按 `self._tools_active()` 自动选择详略：**工具可用 → 简要；降级到文本协议 → 仍给完整清单**
  （文本协议是唯一通道时必须列全，否则模型不知道写什么标记）。
- 顺带修：启动日志打印成 `valpha-0.206`（版本号自带 alpha- 前缀，日志不该再加 v）。

### 效果（同一场景复测）

| | 修复前 | 修复后 |
|---|---|---|
| 生成用 system | 3702 字（≈2314 tokens） | **1747 字（≈1092 tokens）** |
| 能力段占用 | 2059 字 / **55.6%** | **104 字 / 6.0%** |
| 每轮节省 | — | **≈1955 字 / ≈1220 tokens（-53%）** |

现在 system 里最大的段是【说话风格】341 字（19.5%）——那是人设核心，保留合理。

## 本轮遗留（后续轮候选）

1. **一轮 3~5 次模型调用**（生成 + 润色 + 判定 + 表情包判定 ± 工具轮次）→ 用户等待 3~6 秒；可考虑合并小判定、按需润色
2. `emoji.send_probability` 实际存的是 **0.25**（建议 0.5~0.7，属你的配置选择，我只提示不擅自改）
3. 你的配置文件里还没有 `mindstream` 段（0.204/0.205 新增），面板保存一次即可写入
4. deepmemory 侧尚未体检（召回质量/时间线），留待后续轮
