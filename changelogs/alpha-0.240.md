# alpha-0.240

## 修「模板占位符三处定义各写一份，长期漂移」

### 现象（用户提问引入）

1. **新装的机器上，默认模板没有把占位符全用上**；
2. **`{回复}` 这个占位符在别的模块从没见过**，不知道它从哪来；
3. **润色页的占位符芯片和「拦＆改」页不一样**（15 个 vs 19 个），但两条链路其实该是同一套。

### 根因：同一件事被写了三份，各自漂移

| # | 漂移 | 说明 |
|---|---|---|
| ① | **代码默认 ≠ schema 默认** | 代码 `intercept.DEFAULT_TEMPLATE` 是 19 个占位符的完整版；而 `_conf_schema.json` 里长期挂着**11 个占位符的旧版**。**AstrBot 会用 schema 默认值补齐配置** → 新装机拿到的就是旧版，代码里那个完整默认**从未生效**。0.184 那次自动升级只认"0.184 前的那一串"，恰好漏掉这一版。 |
| ② | **`{回复}` 的归属没写清楚** | 它定义在 `TEMPLATE_PLACEHOLDERS`（语义：待改写/待润色的那段原文），但**只有润色链路会给它赋值**（`reply_polish.py: anchors["reply"] = raw`）；接管链路从不赋值 → 它在那里恒被替换为**空字符串**。而代码默认模板里偏偏带着一节「【若需要改写/润色的内容】{回复}」→ 每次都在 system 里留一段空标题。 |
| ③ | **两页各写一份芯片** | 拦截页 0.178 已改成"后端下发清单"，**润色页却还是前端硬编码的旧数组**（15 个）→ 正好少 `{穿搭}{生图意愿}{搜索结果}{回复}`。同一个 bug 只修了一半。 |

### 修复（以"单一来源 + 测试锁死"为主，不只是改文案）

1. **schema 默认值与代码默认值逐字一致**（脚本从代码生成，不手抄）✓ 并去掉恒为空的 `{回复}` 段（新默认 = 18 个占位符）。
2. **占位符作用域**：后端 `placeholder_list()` 增加 `scope` 字段（`{回复}` → `polish`）；
   前端**两页共用** `bindTemplateEditor()` 渲染芯片 —— 不属于本页的标灰 + 悬停说明「仅润色模板有效；在本页会被替换为空字符串」。
3. **「未使用占位符」提示**：模板编辑区下方实时显示还差哪些占位符；**只统计本页适用的那些**
   （否则拦截页会把 `{回复}` 算成"你没用"，反而误导），并说明"另有 N 个只在另一个模板有效"。
4. **旧默认自动升级扩充**：识别**两版**历史默认（0.184 前那版 + 长期挂在 schema 里那版），
   命中则升级为当前完整默认；**自定义过的模板一律不动**（含用户自己写的 `{回复}`）。
5. 顺手修掉迁移日志里写死的「共 17 个」（默认已到 18）——改为从模板本身数出来。

### 用户本机现状（供参考，不需要手动改）

你本机的 `intercept.template` 是 253 字的**自定义/历史版本**（17 个占位符，缺 `{思绪}`、`{搜索结果}`）——
它**不等于任何历史默认值**，所以本轮升级**不会动它**；页面下方那个「未使用占位符」提示会告诉你还差哪些，
想补齐可从芯片点选。`rewrite.template` 仍是出厂默认（8 个占位符），正常。
