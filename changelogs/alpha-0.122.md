# alpha-0.122

## 全链路失败行为审计（你要求的）

先确认「超时失败时 bot 会不会发消息」的现状：

| 链路 | 失败行为（审计结论） | 会发消息吗 |
|---|---|---|
| 媒体会意（识图/文档/链接） | gather 并行 + 每项内部兜底；失败 → 不注入，主链/接管照常回复 | 会（正常回复，仅缺内容） |
| 接管改换生成（90s 超时/空内容） | 静默阻断（stop_event） | **不会**（用户等不到回复） |
| 接管走主链 | 无自调失败（放行主链） | 主链回复 |
| 放行模式注入失败 | 继续主链 | 主链回复 |
| 主动消息生成/发送失败 | 报错台记录，不发送 | 不会（有意克制） |
| 状态/日程/衣柜等一键生成 | 前端提示失败 | 不发送 |

真正「bot 一句话都不回」的只有**接管改换**生成失败/超时。

## 「调用超时后的回复」设置栏

- `general.timeout_reply`（设置页底部栏，textarea 可编辑）：留空 = 保持静默；填写 = 接管超时/失败时直发这段文案（如「抱歉，我刚刚卡了一下，能再说一遍吗」）。
- **发送机制**：`event.send` 平台直发（与主动消息同一路径）——不进 AstrBot 会话历史（respond 阶段只处理 set_result 的结果；直发不写 history）、不触发记忆插件捕获（无 on_llm_response、无事件重入）→ 它是 Bot 的「报错」，不是对话，不会被 astr/记忆插件记录。
- 兜底：无 send 接口的非常规事件走 set_result（个别版本可能记历史，属外层兜底）；发送失败静默。
