# alpha-0.265

## 现象

「从一个主标签页换到下一个，标签显示换了，内容还是原来那页的。」

## 根因（这是真 bug，不是错觉）

`render()` 里有 **29 个 `if (state.current === X) renderX()`，全是并行不等待**，
而每个 `renderX()` 内部各自写 `view.innerHTML`。

于是切页时序是这样的：

```
你点「判定」
  → state.current = "judge"
  → 触发 renderJudge()（发请求，等…）
  → 同时上一步 renderMemory() 的请求才回来
  → renderMemory 写 view.innerHTML = 记忆页内容   ← 覆盖了
  → 你看到：标签是「判定」，内容是「记忆」
```

**网络越慢、页面越重，越容易复现**。

## 修法（三层）

1. **切页瞬间立即清空 view**：显示「切换中…」。
   旧内容立刻消失，不会再出现"看起来没变"。
2. **29 处渲染改为 `await` 串行**：同一时刻只有一个页面在写 DOM。
3. **末尾序号校验**：`state.renderSeq` 在每次 `render()` 递增；
   渲染结束时如果发现序号变了（期间又切走了），**重新渲染当前页**。
   这一条保证"最终一定显示正确的那页"，即使前两层都被绕过。

## 验证

- 代码自检：`await renderOverview()` / `await renderJudge()` / `await renderActing()` 各 1 处；
  `state.renderSeq` 4 处（声明、递增、校验、日志）；`切换中…` 1 处；`渲染序号过期` 1 处。
- 手工复现路径：重载后在「记忆」页停留 1 秒内点「判定」，应当看到「切换中…」然后正确显示判定页。

## 为什么以前没暴露

以前页签少、每页请求快，竞态窗口小。这次加了「守则」「判定」两个都发请求的页，
并且判定页要读 `judge/stats`（涉及 7 个判定器的 provider 解析），窗口变大，问题就显出来了。

## 已知代价

串行会让"从重页切到轻页"时稍微慢一点（要等上一页的请求结束）。
换来的是**内容一定正确**。如果以后觉得慢，应该改的是"每个 renderX 内部先画骨架、
数据回来只补局部"，而不是回到并行覆盖。
