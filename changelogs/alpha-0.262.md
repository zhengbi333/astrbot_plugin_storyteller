# alpha-0.262

## 一、六处判定全部改成 LLM 优先（规矩 R6）

| 判定点 | 原来 | 现在 | 绑定配置 |
|---|---|---|---|
| **情绪事件** | 关键词（`match_keywords`） | `judge.EMOTION_EVENT` | `emotion.provider_id` |
| **撤回** | 关键词（`should_recall`） | `judge.RECALL_NEED` | `recall.provider_id` |
| **记忆去重** | 二元组相似度 | `judge.MEMORY_DUP` | `memory.profile_provider_id` |
| **约定结算** | 二元组相似度 | `judge.PROMISE_SETTLE` | `promise.provider_id` |
| **表情偏好** | 关键词 | `judge.EMOJI_PREF` | `emoji.judge_provider_id` |
| **搜索意图** | 关键词（`_SEARCH_INTENT_RE`） | `judge.SEARCH_NEED` | `search.provider_id` |
| 生图意图 | 规则先行（0.260 前） | `judge.IMAGE_KIND`（0.260 已改） | `image.judge_provider_id` |

**每一处的兜底都保留**：LLM 不可用/超时/超额度时，仍然走原来的关键词或相似度，
只是那一次的结果由规则给出（面板上能看到"兜底"计数在涨）。

## 二、为什么这些判定必须用 LLM（不是"更准"，是"规则根本做不到"）

| 判定点 | 规则为什么不行 |
|---|---|
| 情绪事件 | 「你一点都不讨厌」含"讨厌"却被判成恶意的攻击；撒娇「你可真会说话」被当成讽刺 |
| 撤回 | 「你能不能别理解成这样」是纠正，但没有任何一个固定词 |
| 记忆去重 | 「做了 PPT」vs「做了个幻灯片」——字面重合度极低，却是同一件事 |
| 约定结算 | 约定「给你做份汇报」vs 行动「生成了季度总结.pptx」——表述完全不同 |
| 表情偏好 | 「能不能别老发这些」——没有"别发表情"这四个字 |
| 搜索意图 | 「查一下日程」和「查一下 5090 价格」长得一样，一个本地一个联网 |
| 生图意图 | 「做一份文档」里的「做」被当成绘画动词（真机事故） |

## 三、面板新增「判定」页签

**你要求"新增的判定模型必须在面板里显示"，已做**：

- 顶部四格：判定器数量、LLM 判定次数、退化成规则次数、**退化率**
- 每个判定一行：判定名 + 候选值 + **配置键** + **实际模型** + LLM/缓存/兜底次数 + 剩余额度
- 标签区分「已单独配模型」和「回退统一模型」

退化率 > 50% 时会高亮 —— 那说明模型基本没在用、判定其实退回规则了。

## 六、已知边界

- 判定面板的计数是**进程内**的（重启归零）—— 它不是账本，是"当前在不在用 LLM"的体检；
- 每个判定器日限 300 次是**单类**计数，不是总数；
- LLM 判定会多花一次调用（6 秒超时），所以在"规则命中之后、动作执行之前"跑，
  失败就退回规则，不阻塞回复。
