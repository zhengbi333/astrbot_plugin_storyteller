# alpha-0.252

你知道的那个现象：发「笑一笑」+ 一张图，她**只回了那张图**（「发图我也笑不出来」），
和上文完全割裂。

## 一、先查清原因（不是"媒体没进防抖"）

查了你的实际配置：`debounce.window = 2.0`、`min_wait = 1.0`、`max_wait = 6.0`、`smart_judge = true`。

你的节奏是：

```
17:26:36  嘛…语气干嘛那么僵硬嘛
17:26:39  笑一笑            ← 3 秒后（窗口内，合并）
17:26:43  [表情图]           ← 4 秒后（窗口已经结算了！）
```

2 秒窗口在你打字+发表情这 7 秒里**结算了两次**，图落到第二个窗口，单独触发了一次回复。
媒体其实**是**进了防抖（`_extract_content` 会返回 images），问题在**窗口太短**。

## 二、修法：纯媒体跟随上一条时视为"补充"

不改你的配置（窗口是你在用的值），改判定逻辑：

| 条件（全满足才吞） | 说明 |
|---|---|
| 这条**没有任何文字**，但有图/表情/文件 | 带文字的图文仍正常处理 |
| 这个会话**刚刚**有过一条消息（默认 12 秒内） | 20 秒后单独发图仍会回应 |
| `debounce.media_followup_merge` 打开（默认开） | 可以关 |

命中的处理：**静默吞掉**（不触发回复），只记画像/互动素材 —— 图变成了"上一句的补充"，
而不是一个独立问题。

配置：`debounce.media_followup_merge`（默认开）、`debounce.media_followup_seconds`（默认 12，夹 3~30）。

## 三、验证

`_st_test/audit_79_media_merge.py` —— **18/18**：

- 判定 6 项（首条不吞、2 秒内吞、20 秒后不吞、带文字不吞、空消息不吞、文件也算媒体）；
- 开关 3 项（关掉不吞、自定义间隔上/下界）；
- 间隔读取 3 项（默认/下限/上限）；
- 接线 6 项。

## 四、已知边界

- 只处理"纯媒体紧跟其后"；**图文同一条消息**本来就是合并处理的，不受影响；
- 吞掉意味着"只发图不说话"时她**不会回应**（12 秒内的情形）—— 这是有意的取舍；
- 如果你希望她偶尔对表情包有反应，就把 `media_followup_seconds` 调小（比如 5）。
