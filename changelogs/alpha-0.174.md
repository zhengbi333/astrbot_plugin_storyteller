# alpha-0.174

> **⚠️ 已回退（见 alpha-0.175）**：本版本的预算增大基于模拟器/探针"未带关闭思考参数"的裸调用误判。生产直连默认 `disable_thinking=True`，模型不推理、在预算内直接输出（实测约 6 秒完成）；故 0.175 已将日程/日记/状态预算回退原值 4000/1600/800，仅保留「空输出不重试+明确报错」防御。

## 实验性预算增大（误诊，已回退）

- **现象**：全真生活模拟器（真实 LLM）中，日程自动生成解析失败（原文 0 字）、跨天前失败、深夜写日记不写；用户此前实测同样"后台自动生成日程，输出截断/为空"。
- **排查（直连 API 探针，多次采样）**：
  - deepseek-v4-flash-vision-exp 是**推理模型**：日程提示词（约 1.2k 字）需要 **5.2k~8.5k reasoning tokens（次间波动大）** 才得出最终 JSON；
  - `max_tokens=4000`：`finish_reason=length`，`completion_tokens_details.reasoning_tokens=3999` → **content 为 0 字**（全部预算被推理吃掉），重试一次必空（白白多花约 4k tokens）；
  - `max_tokens=8000`：多数情况正常（reasoning 5531 + content 1096），但**仍偶发吃光**（实测一次 71s 后 content 0 字）——推理长度次间波动可达 8k+；
  - `max_tokens=12000`：实测稳定（reasoning 5242 + content 1178，`finish_reason=stop`）；
  - 总结类提示词（约 260 字）只需 reasoning 39 + content 186，1200 预算足够——但同样的"推理优先、长度截断"风险存在于所有生成型调用。
- **修复（0.174）**：
  1. `_generate_schedule`：`_max_tokens` 4000 → **12000**（8000 仍偶发吃光，12000 缓冲充足）；
  2. `_write_diary`：`_max_tokens` 1600 → **5000**（日记也是"先推理后正文"的创作型任务，1.6K 会被推理吃光→空日记）；
  3. `_refresh_presence`：`_max_tokens` 800 → **2000**（状态锚同风险）；
  4. **空输出跳过无意义重试**：首次输出为空（推理预算占满）→ 直接报「模型未输出内容（推理预算被占满，请稍后再试或换模型）」，不再重试；仅在「有内容但解析失败」时按 0.173 逻辑重试一次。

## 验证

- 全真生活模拟 20 项全绿（日程自动生成 / 跨天重新生成 / 深夜自动写日记 / Token 记账等全部通过）
- 41 项冒烟 0 失败
