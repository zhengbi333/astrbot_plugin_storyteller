# alpha-0.161

## 修复：实机索要的最终根因——user prompt 的「请以以上设定的身份、本次对话上下文」被模型转引成索要话术

- **背景**：用户追问"到底发给 LLM 什么内容"。0.160 诊断日志 + 完整还原确认：**注入链路从未坏**——
  - `接管系统提示(排查): len=1431 含阡墨=True`——阡墨 322 字、防认错锚 273 字、关系（陌生/放松/**称呼证毕**）、风格（寡言温和+口头禅）、状态（午后平稳）、日程（整理工位）、当前说话（你好）全部注入；
  - **唯一带"设定/上下文/身份"字样的句子 = user prompt**："请以**以上设定的**身份、**本次对话上下文**，自然回应对方刚刚说的话。"
- **证据**：17:00 模型回复"抱歉，我没看到具体**设定和上下文**……这样我好**代入**回应你"——"设定和上下文"两词只可能来自该句；12:42 模型明确引用过"**以上设定**"。
- **结论**：模型把 user prompt 的"设定/上下文"当成"用户应该提供但没提供的东西"，越提示越索要（"诚实"模型的上下文引用行为）。

## 修复
1. **user prompt 重写**："请以以上设定的身份、本次对话上下文，自然回应对方刚刚说的话。" → "**直接回应对方刚刚说的话，像平时聊天一样。**"——删除"设定/身份/上下文/以上/本次"全部可转引词。
2. **final_system 尾部去框架注**："注意：你就是上方那个人，不是演员、不是助手；对方这句话就是全部，直接回答即可。"（不带任何敏感词）。
3. **索要检测宽召回**（`_looks_asking_context`）：词表扩展（代入/描述一下/再描述/前文对话/没有看到/没看到/看不到/请再/重新发/麻烦你 等）+ **道歉式强信号**（含"设定"或"上下文"+ 抱歉/没看到/不知道应该以/我这边没有 + ≤100 字 → 直接命中）。宁可多拦：拦错只是多一次重生成，正常句子零影响。
4. **重生成改「去框架最小提示」**：不再复用模板框架（"【你是「为你续写的故事」里的角色】/请以这个角色的身份"本身就是"代入设定需求"的温床），改用独立提示——"你叫：{阡墨全文}。对方是在和你私聊的：{用户}。对方刚刚说：{原文}。你就是真实生活里的这个人本人，不是在扮演、不需要代入任何情境。直接以本人平常的口吻回一句：不问问题/不提设定/不介绍自己/不解释。"
5. 失败链不变：检测 → 去框架重生成 → 仍索要 → 固定短句"嗯，在呢。想聊点什么？"。
