# alpha-0.159

## 修复：实机「索要设定」闭环——提示词索要词诱导 + 硬兜底 + 排查日志器名修复

- **现象**：0.158 实测 /reset 后「你好呀？」→ 3 条回复："你好。" + "不过我还不知道具体该以什么角色、在什么情境下说话。能补充一下吗？"——**接管模型（12:42:20 日志原文 len=72 "我没有看到具体的'身份设定'或'对话上下文'…能补充一下吗？"）索要 + 润色模型忠实润色（补了"你好。"）**。
- **真根因（三层）**：
  1. **提示词索要词诱导**：防认错锚"…不要追要所谓「设定」"、上下文占位句"（本次会话从这里开始，没有更早的对话记录。）"、模板"角色/情境"字样——模型在**问候式疑问句 + 上下文/记忆空**时，把提示词里出现的「设定/上下文/角色」当成"需要向对方索要的东西"（12:14/12:33/12:42 全部命中；12:13 正常因当时时间线还有真实记录，无占位句）。
  2. **占位句适得其反**：0.157 的上下文占位句提及"没有更早的记录"，反而强化"设定在更早对话里、现在缺失"的联想。
  3. **排查日志器名 bug**：reply_polish.py 临时日志用的 logger 是 `astrbot_plugin_storyteller`（下划线），而插件日志器是 `astrbot.plugin_storyteller`（点）——日志进了无人监听的 logger，导致润色真实行为一直看不见。
- **修复**：
  1. **删索要词**：防认错锚删"不要追要所谓「设定」"（保留"直接按对方的这句话回应即可"）；接管两路径**删除上下文/记忆占位句**（留白即正常，防认错锚已不再承诺"已含"，无空白陷阱）；关系/风格占位措辞去"设定"字样（"还没定说话风格，自然表达即可。"）；润色 persona 占位改"（暂无额外角色说明——你就是一位自然、友好、普通的聊天对象。）"。
  2. **索要检测 + 重生成硬兜底**（`_looks_asking_context`：提及"设定/上下文/角色/情境" + 索要句式双条件，正常提及不误伤）：接管生成若命中 → 带"你就是人格/身份里的人本人、严禁索要"**重生成一次**；仍索要 → 固定自然短句"嗯，在呢。想聊点什么？"。**无论根因如何，模型都不再可能把索要句发给用户。**
  3. **排查日志器名修正**：reply_polish.py 全部日志改 `astrbot.plugin_storyteller`（与插件日志器一致，写入 storyteller.log）。
- **注**：0.158 的润色空态占位、模板损坏回退（默认模板/原文附录）全部保留。
