## 第一个落地：戳一戳（`send_poke`）

**为什么先做它**：这是**最像真人的小动作**。一句"戳你一下"胜过十句文字，
而且参数最简单（`{user_id}` 或 `{group_id, user_id}`）、风险最低（不写盘、不发内容）。

### 实现方式（守住本插件风格）

**没新开文件、没新开机制** —— 做成 `capabilities.py` 里第 14 个能力，
和 `photo_take` / `emoji_send` 同级：

```python
_register(Capability(
    name="poke",
    title="戳一戳对方",
    description="戳对方一下（QQ 的「拍一拍」）...",
    impl=_impl_poke,
))
```

模型侧看到的是工具 `story_poke`，和记忆/搜索/画图一样。

### 三个设计取舍

**① 参数不让模型填。** `user_id` / `group_id` 从事件里取 ——
模型只需要决定"我要戳他"，不该猜 ID（猜错就戳到别人了）。

**② 群聊自动带 group_id。** 否则 `send_poke` 会被当成好友戳。

**③ 失败一律如实告知。** 平台不支持 `call_action` → 明说；
调用抛错 → 明说"没戳成，别硬说戳到了"。

### 配置化（不写死）

新增 `capabilities.poke_daily`，默认 **10**：
`0 = 不限制（不建议，会被当成骚扰）`。这个动作很显眼，宁可少一点。

## 验证（`audit_96_poke.py` 21/21）

- **A** 注册：在能力表里、有标题、说明里写了「用/不要用」、有日限键、有示例；
- **B** 私聊：只传 `user_id`，不带 `group_id`；
- **C** 群聊：带 `group_id` 且同时带 `user_id`；
- **D** 失败：调用失败 `ok=False` 且提示"别硬说"；平台无 `call_action` 时明说；
  拿不到对方 ID 时拒绝；
- **E** 配置：`poke_daily` 在、默认 10、有 hint；
- **F** 工具名前缀 `story_`、实现函数在。

## 已知边界

- 只做了戳一戳，**没有做"她主动决定什么时候戳"**的策略（现在是模型看到工具后自己判断）；
- 日限靠 `capabilities` 已有的计数机制，和画图/表情共用同一套；
- SnowLuma 的 `send_poke` 在群聊里需要机器人有对应权限（某些群会限制）。
