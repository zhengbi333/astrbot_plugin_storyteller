# alpha-0.95

> 本版依据实机日志（0.94 部署后）迭代：开关保存已实证修复（`True/False` 真布尔落盘）；日程生成流水线实证跑通（流式风暴早停 → 非流式兜底 72 秒成功落盘 18 段日程+穿搭），但暴露出「确定性失败仍重试」的时间浪费与「思考上限偏紧」两个问题。

## 确定性失败不再重试（省 1~2 分钟空等）

- 新增内部异常 `_StreamEarlyAbort`（思考风暴 / 内容跑飞超长）：这类失败由提示词与模型行为决定，**重试同一提示词几乎必然同样失败**——旧逻辑仍按 `stream_retry` 重试，实机浪费 2~3 次尝试（每次 24~57 秒）。
- 现在：确定性放弃 → **跳过重试、直接回退非流式**；而超时/断网等偶发失败仍按 `stream_retry` 正常重试（冒烟新增「偶发超时仍重试」反向断言）。
- 实机对照：原流程 3 次流式空试（~110s）+ 非流式 72s ≈ 3 分钟；现流程 1 次流式（~24s）+ 非流式 ≈ 1 分半。

## 思考长度上限默认值 8000 → 24000

- 实机发现：推理模型对开放式创作提示词的**正常**思考约 1 万+字符——8000 会把「思考较久但能正常答完」的模型误杀。
- 新默认 24000≈容忍较长的正常思考，同时把明显跑飞（几万 Token 空想）截在超时前；可配置（设置 → 模型配置）。**已保存过 8000 的老配置不会自动变**，建议手动调到 24000。
- 该机制与具体提供方无关：按思考字符数截断，任何家模型都适用。

## 新增：日程页「生成提示词」预览面板（只读，零 Token）

- 用户要求：展示一键生成日程时发给直连模型的完整内容并加以说明。
- 路由 `GET schedule/prompt_preview`：复用与真实生成**完全相同**的构造器与素材来源（不调用 LLM、不消耗 Token），返回提示词原文 + 实际生效模型 id + 素材清单。
- 日程页底部新展示板卡片：列出 8 类素材的拼入情况（✅/➖ + 内容前 80 字预览）：任务模板（固定）、人格/风格（voice.tone）、此刻状态、天气、记忆约定/愿望（最近 6 条×80 字）、衣柜名单、未来规划（≤5）、延误事项（≤5）；下方为提示词原文（pre 滚动展示）。
