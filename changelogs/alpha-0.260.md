# alpha-0.260

## 规矩 R6（从今天起，最高优先）

> **能调用 LLM 做智能判定的，就不要写规则。**

规则的问题不是"不够准"，而是**它会短路**：一旦命中就直接 return，模型连被问的机会都没有。
真机事故就是活证据 —— 「你做一个文档」里的「做」被当成绘画触发词，「一个」被当成画图量词，
生图模块判定"要画图"并直接发图，**LLM 从没参与，工具更没机会**。

**正确形态**：

```
① 缓存命中 → 直接用（省钱省时）
② 调 LLM 判定
③ 解析成功 → 用模型的判断
④ 任何失败 → 用规则的判断（只能保底，不能抢先）
```

## 新建 `judge.py`（统一判定层）

| 判定器 | 候选 | 用途 |
|---|---|---|
| `image_kind` | 画图 / 文档 / 其他 | 这句话要什么（替代生图规则先行） |
| `search_need` | 要查 / 不用 | 是否联网查（替代搜索关键词） |
| `emotion_event` | 被骂/被夸/被表白/被撒娇/被冷落/被关心/吵架/普通 | 情绪事件（替代关键词） |
| `recall_need` | 要撤回 / 不用 | 是否在纠正她（替代关键词） |

**成本控制**：同一文本缓存 10 分钟、每判定器日限 300、超时 6 秒、输出限定一个词。
`stats()` 给面板看每个判定器用了几次 LLM / 缓存 / 兜底。

## 本轮整改：生图判定

- **原**：`detect_image_intent` 规则命中 → 直接生图并 return
- **改**：先问 LLM「画图 / 文档 / 其他」，只有 LLM 不可用时才信规则
- **验证**：真机原句「你做一个文档，发我，内容是…」→ 判成「文档」，不生图；
  「画一张猫」→ 判成「画图」；

## 已知边界

- LLM 判定**比规则慢**（6 秒超时 + 一次调用），所以放在"规则命中之后、动作执行之前"；
- 没有 provider 时全部退化为规则 —— 这时行为和以前一样；
- 判定器只输出**一个词**，避免模型啰嗦导致解析失败。
