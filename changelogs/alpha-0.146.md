## 全面自检轮：修复记忆注入托管失控 bug（用户要求全面自检双插件）

### 🔴 修复：记忆插件自动注入被意外永久关闭（确凿 bug）

- **现象**：storyteller 旧 `_ensure_memory_managed()` 在 `on_llm_request` **开头无条件**执行——只要装了 storyteller 且「记忆托管注入」开着，就把【为你篆刻的历史】的自动注入关掉（`set_injection_managed(True)`）。而托管状态被关的
  - 「拦截参与总开关**关闭**」模式下：storyteller 完全不参与 → 主链请求**拿不到任何记忆**；
  - 「**监视**」模式：storyteller 也不注入 → 主链请求**无记忆**；
  - 「接管改换 / 阻断」虽然主链被阻断，但状态残留同样影响后续请求；命令消息路径同样提前托管。
- **修复**：改为 `_sync_memory_managed(enable)` **按每次请求的模式动态同步**：
  - 本插件将注入（**放行** / **接管走主链**）→ 托管 True（记忆插件跳过自动注入，防双份）；
  - 本插件不注入（监视 / 阻断 / 接管改换 / 命令消息 / 拦截关闭）→ 托管 False（恢复记忆插件自动注入，记忆不再消失）；
  - 用户手动关闭「记忆托管注入」→ 一律恢复记忆插件自动注入；
  - 状态无变化不重复调用桥接；桥缺失不报错、后续事件自动重试；卸载时恢复托管（既有 terminate 逻辑保留）。
- **专项回归** `smoke_memory_managed.py`（15 项）：放行托管 True 且注入、同状态不重复 set、监视/阻断/接管改换/拦截关闭/命令/托管关闭 → False、桥缺失容忍、True→False→False 翻转只 set 两次——全绿。
- 联动核对（无问题）：接管模式总结不饿死——storyteller `_note_bot_reply` → `record_visible_turn` → `maybe_summarize_session` ✓；防抖合并期间的每条消息由 deepmemory 消息级捕获 + message_id 去重 ✓。
