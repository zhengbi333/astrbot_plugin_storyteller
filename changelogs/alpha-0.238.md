# alpha-0.238

## 两个来源：朋友实测「她为啥还在发这个」+ 你指出的两个设计问题

### 现象（朋友 QQ 端实测）

| 时间 | 内容 |
|---|---|
| 18:36 | 她说「白猫那张画我都画好晾半天了……再不来我可要收走了。」→ 对方「**哎呀，已经看过了**／很不错嘛」→ 她说「哦，看过了啊……那还差不多」「……这次就勉强放过你吧」→ **话题已结项** |
| 21:22 | **主动消息**：「**画完那只猫了**，阳光角度调了好久，总觉得差点意思。」✗ **把已经结项的事又当"未完成"重提了一遍** |

对方反馈：「我们已经说过这个话题了」；你补充两条要求：**① 发出去（= 这件事被处理过）就该减权/结项，不能一直重复；②「立即尝试一次」不该被"刚聊过"卡住**。

### 一、为什么它会重复（代码级定位）

| 检查项 | 结论 |
|---|---|
| 主动素材从哪来 | 由头引擎汇集：状态(0.35) / 日程(0.4) / **记忆-约定(0.5)** / 见闻(0.45) / 梦(0.55) / 事件源 / **约定后续(0.6)** |
| 为什么偏偏是它 | `pick()` **按重要性最高优先** → 约定类两条源（0.5 / 0.6）几乎总能赢 |
| 为什么结项了还留着 | `_recent_promise_hint()` **无条件取最近 4 条 promise 记忆**，没有任何"办完了没"的判断 |
| 为什么当天没拦住 | "已提过"去重只记**主动发过**的（`used_pairs[day]`），而 18:36 是**正常对话**里结项的 → 无人登记 |
| **更深的坑** | 由头引擎的登记表 `_meta` **根本没落盘**（只存内存）→ **每次重启，"已提过/已结项"全部复活** |
| 另一处失忆 | `proactive._last_interaction` 也没落盘 → 重启后 `last_reply=0 < last_sent`，**误判"对方没回应我"** → 自动把间隔越拉越长 |

### 二、修复（行为）

1. **已了结的约定不再当由头**：新增 `promise_settled()` **两级判定** ——
   ① 主题级：最近对话与约定文本的字符二元组交集够多（≥3 个或占比 ≥25%）；
   ② 完成级：最近对话里存在一句**同时**「与约定沾边」+「带完成/收到标记」+「不是未来时」。
   实测抓出的证据句正是那句：「白猫那张画我都画好晾半天了……再不来我可要收走了」；
   而「还在画，阴影还得再改改」「明天就画好了」「还没查，晚点看」都**不会**被误判为已了结。
2. **约定类由头跨天冷却 2 天**（`cooldown_days`）：原来只管"当天"。
3. **发送成功后消化由头**（你的要求①）：主动消息**真的发出去**后，把这条约定记忆
   **权重降到 60%**（走记忆插件的 `update_importance`）；**累计提过 2 次即结项**，此后不再当由头。
   发送失败则不消化（下轮仍可重试同一条）。
4. **「立即尝试一次」不再受"刚聊完"限制**（你的要求②）：`_should_send(force=True)` 跳过
   `cooldown_after_chat_minutes`；**免打扰时段 / 每日上限 / 静默闸门仍然生效**（手动也不该半夜炸醒对方）。
5. **提示词两条新约束**：由头若与「你们最近聊到」重复就作废、宁可不说；开口要面向对方，
   **不要用「我把X做完了/弄好了」这种汇报自己进度的开场**。

### 三、落盘完整性专项（你追问「还有多少没落盘」）

我此前逐模块审计**没有专门查落盘**，这是盲区。这轮把两个插件的**全部运行时状态容器**盘了一遍
（storyteller 48 个 / deepmemory 11 个），逐条判定"丢了会不会影响行为"，结论：

**已补落盘（此前只在内存、重启即失，且确实影响行为）**

| 状态 | 失忆后果 | 处理 |
|---|---|---|
| `proactive._last_interaction` | **"刚聊完顺延"失效 + 误判对方没回应 → 间隔越拉越长** | 写入 `proactive_meta.json` |
| `proactive._sent_history` / `_candidates` | 面板「已发送」「候选判定」重启后清空（你正是靠它排查） | 同上（各留最近 200 条） |
| `proactive._daily_per_user` | 面板「今日已主动」每人计数归零 | 同上 |
| `_silence_streak` | 连续沉默上限的保护被重置（正是你关心的沉默行为） | 新增 `runtime_state.json` |
| `_cap_usage` | 能力每日限额被重启"清零"（可被重启绕过） | 同上 |
| `InspirationEngine._meta` | **"已提过/已结项"全部复活 → 同一件事反复说** | 新增 `inspiration_meta.json`（按天表保留 14 天，结项长期保留） |

写盘策略：**节流**（距上次 ≥20 秒才真写，避免每条消息都落盘）+ `terminate()` 强制刷一次。

**有意不落盘（设计如此，不是漏）**：口癖检查窗口 `_my_recent_replies`（其注释写明"只看最近几轮、
重启后重新积累即可"）、各类短期缓存（搜索结果/图片意愿/记忆写入幂等/表情包补发幂等/进行中请求）、
debounce 与 reply_buffer 的**在途**状态、`_thumb_cache`、deepmemory 的 `_session_personas`
（随每条消息重建，且关键路径都显式解析人格）、`_bg_tasks` / `_inflight` 等任务句柄。

**核对纠错**：扫描曾把 deepmemory 的 `_last_maintenance_at` 列为未落盘，实查它**已通过**
`store.set_setting("last_maintenance_at")` 落盘 —— 是我的正则没匹配到，不是缺陷。
