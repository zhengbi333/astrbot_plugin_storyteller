# alpha-0.218

## 25 模块深度自检 · 第 4 轮：image 生图（**含一次对我自己误报的修正**）

### 执行链核实

用户在对话里索图 → `_maybe_handle_image_intent()`：

① `_resolve_image_intent()` **三分层**判定
（A0 规则直判 → A1 索图短问 + 上文主题锚定 → B 轻量 LLM 仲裁，实验开关）
→ ② `image_gen.can_generate()` **三道门槛**（模块开关 / 每日上限 / 独立 API 配置完整性）
→ ③ `_compose_image_prompt()` 注入人格·气质·状态·穿搭·天气·活动
→ ④ `image_gen.generate()` → ⑤ 发送（图片 + 说明，`image.caption` 可留空）
→ ⑥ 回填记忆时间线与会话历史 → ⑦ `_stop_llm` 阻断主链防双回复

**未命中 / 达上限 / 未配置 / 生成失败 → 一律不阻断**（放行聊天，避免用户被晾着）✅ 设计正确。

### 实测 1：意图分层（真实话术）全部正确

| 话术 | 上文 | 结果 |
|---|---|---|
| 画一张猫 / 帮我画只橘猫吧 / 生成一张星空图 | — | 命中 → 猫 / 橘猫 / 星空图 |
| 拍个照发我 | 你那边的云怎么样 | 命中 → **云的景象**（泛词锚定到上文主题，不画人像） |
| 给我看看 | 今天晚霞好美 | 命中 → **晚霞的景象** |
| 帮我看看日程 / 看看这个文件 | — | 不命中（非画面任务词） |
| 你皮肤怎么样 | 你看我新买的裙子好看吗 | 不命中（**防误吸**） |

### 实测 2：弱信号走「生图意愿」而非硬生图（5/5）

「今天晚霞好看吗」+ 上文在聊画面 → 不硬生图，改为打标签：
> 【画面话题】对方可能想看一眼画面（上文在聊「晚霞」）——如果你觉得对方想看，可以自然地问一句要不要拍给他看；
> 但「好看吗/啥样」只是询问，别当成必须执行的要求。

无画面上文时**不打标签**、非画面闲聊也不打 ✅

### 我修正的问题：第 2 轮的生图自检项报了**误报**

- 第 2 轮我写的 `image_status` 按 `image.provider_id` 判定「没配生图模型 → 无法生成」；
  但**真实门槛用的是 `api_enabled / api_base_url / api_api_key / api_model`** 一组键 ——
  用户这组键**全都配好了**（siliconflow + `Tongyi-MAI/Z-Image-Turbo`，每日上限 5），
  **生图本来就能用**，是我给了错误警报。
- **修复**：`image_status` 改为**复用真实门槛**（`image_gen.backend()` / `._endpoints()` /
  `._daily_used()` / `._missing_fields()`），与生成逻辑同源。
- 修后实测：`生图可用（后端=api，今日 0 张，上限 5；历史 0 张）` ✅
- **连带作废**：第 3 轮 changelog 里"到生图页选中 Z-Image-Turbo 即可修复生图"的建议**不成立**（你早已配好）。

### 教训（记入手册第 5 条）

**自检/诊断代码必须复用被测逻辑本身**（同一个门槛函数）。自己另写一套判定，迟早会出现
"诊断说不通、实际能用"或反过来的误报——这次就是活例。
