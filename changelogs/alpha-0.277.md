# alpha-0.277

## 你说对了：我们是直连，不存在「透传」问题

主链接管改换走的是 **LLM 直连**（`models.py` 自己发 HTTPS），
绕开 AstrBot 的 provider 封装。所以：

| 通道 | 能否拿到 `prompt_cache_hit_tokens` |
|---|---|
| **主链（直连）** | ✅ **一定能** —— 响应是原始的，DeepSeek 原生返回 |
| 辅助调用（走 AstrBot provider） | ❌ 看不到，但那些是短 prompt，本来也没缓存意义 |

**「透传」是施工图里抄来的词，不适用我们的直连通道。** 上一轮的观测不是在赌。

## 这反而说明：system 结构确实该改

直连 + DeepSeek 有 prompt caching，**但缓存要求前缀完全一致**。

查了实际拼装顺序（`main.py:2523` 起）：

```python
final_system = replace_template(template, anchors)   # ← 第一段就是模板
```

而模板里含 `{状态}` `{日程}` `{记忆}` `{内心}` —— **每轮都变**。
**第一段就变了，后面再稳定也没用**，所以前缀命中率必然接近 0。

## 做法：可开关，默认不改行为

新增 `intercept.stable_prefix`（**默认 false**）：

- **打开后**：「扮演守则」（1500+ 字）+「工具规范」（400+ 字）提到 system **最前面**，
  模板与动态内容排在后面 → 前 2000 字左右**每轮完全一致** → 前缀缓存能命中；
- **关闭时**：完全维持现有顺序，行为不变；
- 开关说明里写清了利弊（省 token / 更快 vs 可能影响说话效果）。

## 验证（`audit_93_stable_prefix.py` 14/14）

- **A** 配置项在、默认关、hint 说明利弊；
- **B** 两处都受同一开关控制；关闭时仍有原顺序分支；
- **C** 行为：默认时模板在最前、守则在模板后；打开后守则/工具规范在最前、模板在后；
  **两种顺序内容总量一致**（不会因为换序丢内容）；
- **D** **前缀稳定性实测**：动态内容变化时，前缀部分（守则+工具规范）**逐字节一致**。

## 怎么用

1. 先重载，随便聊 3~5 条；
2. 看 `plugin_data/astrbot_plugin_storyteller/_diag.log` 里的 `缓存观测` 行：
   ```
   缓存观测: cached=812 other=210 命中率=79% system_chars=1523
   ```
3. 如果 `命中率` 一直是个位数甚至 0 → 去面板打开 `intercept.stable_prefix`，再聊 3~5 条对比。

**有数据再改结构，不猜。**
