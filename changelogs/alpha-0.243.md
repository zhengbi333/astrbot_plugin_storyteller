# alpha-0.243

## 一、轮次上限 4 → 8（两处都改）

以前 `capabilities.max_rounds` 有两处硬上限 4：一处是接管链路算 `cap_max_rounds`，
一处是 `_generate_tool_loop` 自己再钳一次。配到 8 也只跑 4 轮 —— 复杂任务做不完。
本版两处都放到 **8**，`_conf_schema.json` 的 hint 同步说明。

## 二、防打转

模型在工具失败时容易**用同一参数反复重试**，烧 token 且毫无进展。新增：

- 循环内按 `工具名 + 规范化参数`（`json.dumps(sort_keys=True)`）计数；
- **第 2 次**：照常执行，但在结果里追加提示「刚才已用同样参数调过一次，结果会一样」；
- **第 3 次起**：不再执行，写入拒绝消息并置 `stop_loop`，下一轮 `tool_choice="none"` 让模型**基于已有结果收尾**（不是硬编一句"做不到"）；
- 判定抽成纯函数 `_repeat_verdict(count)`，便于单测。

## 三、长输出保首尾

`_call_astrbot_tool` 的结果截断从 `[:4000]` 改为 `_truncate_keep_ends(text, 4000)`：
`前 70% + …（中间省略 N 字）… + 后 30%`。工具输出里最关键的东西常在结尾。

## 四、任务执行守则

当**外部工具开启**且 `capabilities.work_rules_enabled`（默认开）时，向 system 追加一小段：

- 分步推进，一步看输出再决定下一步；
- 失败读错误原文再改一版，不要用同样参数反复调；
- 产出文件后用 `toolbox_send_file` 发出去，别只说"已经做好了"；
- 中间过程不要发给群里。

## 五、验证

`_st_test/audit_61_loop_guard.py` —— **28/28**：轮次上限两处都到 8、不再有 4 的硬上限、
`_repeat_verdict` 第 1/2/3/99/0 次行为、循环接线（`seen_calls` / 键格式 / `tool_choice` 受 `stop_loop` / 提示并入结果）、
截断保首尾（短文本不变、首尾都在、省略字数、limit 很小时不越界）、守则注入与开关、schema 默认值。

另跑既有 26 批回归与 `audit_44/51/57/58/59/60/62`。

## 六、说明

- 守则只在"能用工具"时注入 —— 否则她没有动手能力，说了也没用。
- 轮次提高会增加模型调用次数（每个复杂任务多几轮），成本换能力，可按需调回 3。
