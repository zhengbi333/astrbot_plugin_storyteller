# alpha-0.195

## 用户五项反馈修复轮（含"主动沉默"补齐）

### ① 清障页点测试后仍被拉回顶部

- **根因**：0.193 只给 `refreshCurrentView` 与 24 处 `renderXxx()` 接了滚动保护；清障页用的是自己的 `rerenderAll()` / `renderListOnly()`，没接入 → 每次「测试」都回顶。
- **修复**：两处都加滚动快照/恢复（`renderListOnly` 同步恢复；`rerenderAll` 等 `renderTroubleshoot()` 完成后恢复）。

### ② 发送页看不到新策略（"这对吗？没有备注？"）

- **根因**：0.194 只加了配置项，**发送页字段是显式列出的**，没把 `interrupt_mode`/`max_restarts` 渲染出来，所以面板上仍是旧的「抢话裁决」开关 + 旧说明（"关闭则固定按 A"）。
- **修复**：发送页新增两个字段——「抢话处理方式」（作废重理解 / 模型裁决 / 提速发完）与「打断重生成上限(次)」，并把说明文案改写为三种策略的含义 + 生成期连发的重启上限行为；顶部总开关描述同步更新。

### ③ 内心页「见闻」越刷越多、把设置挤下去

- **修复**：见闻列表容器固定高度（`max-height:290px`）+ 内部滚动（不再是"越长越往下顶"）。列表本来就按 3 条/页分页（`PAGE=3`），现在无论积累多少条，占用高度都恒定，设置项不再被挤走。

### ④ 朋友的表情包不发送（关键信息：他建了名为「表情包」的分组并加了图）

- **判定**：他用的插件版本**早于 0.193** —— 0.193 之前"接管改换"链路根本不插入 `[EMOJI:分类]` 占位符（判定只在主链路径生效），因此**无论图库有没有图都不会发**。这正是 0.193 修掉的根因；请把他那台升级到 **0.193+**。
- **本轮补强（0.195）**：新增**明确索要**识别——用户说「发个表情包 / 来个表情 / 给我发个表情」时**直接发一张**（跳过判定模型与概率闸，这是明确指令而非语气判断），避免"用户明明要表情包，判定模型却觉得不需要"。分类按"第一个真的有图的分类"取。

### ⑤ 主动沉默（"不该回的时候不回"）

- **结论**：**主链路径（放行/走主链）一直有**——回复判定模型的 `silence`（不值得回）/`brief`（只草草回一两个字）从早期版本就在 `reply_pipeline.process()` 里；**但接管改换链路绕过了判定**，所以"每条必回"（与表情包发不出同源）。
- **本轮补齐**：接管改换在生成+润色后增加一次**回复判定**（复用同一判定模型与提示词，25 秒超时，失败按正常回复）：
  - `silence` → **本轮不发送**（记录 `判定沉默`，日志含理由）；
  - `brief` → 只发判定给的极短句（`啊？`/`…？` 之类）；
  - **保险**：`pipeline.silence_streak_limit`（默认 2）——最多连续沉默 2 次，达到上限强制回复一次（防误判导致一直不理人）；开关 `pipeline.takeover_judge_enabled`（默认开）可关闭。
- 场景样例：你回「晚安」、对方也回「晚安」→ 判定可沉默；但连续第 3 次必定回一句，不会"装死"。

### 新增/变更配置

| 模块 | 键 | 默认 | 说明 |
|---|---|---|---|
| pipeline | `takeover_judge_enabled` | true | 接管链路是否做回复判定（沉默/草草回复） |
| pipeline | `silence_streak_limit` | 2 | 最多连续沉默几次（0=永不主动沉默） |
