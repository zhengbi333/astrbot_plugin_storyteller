## 25 模块深度自检 · 第 2 轮：troubleshoot 清障

清障页是用户的"体检工具"——它自己覆盖不全，用户就会以为"全绿 = 都正常"。

### 问题 1：7 个模块完全没有自检项（假安全感）

原本 16 项，对照 25 个面板模块，以下 7 个**从未被检查**：
`intercept` 拦截与模板、`debounce` 消息防抖、`rewrite` 润色、`image` 生图、
`wardrobe` 穿搭与衣柜、`mindstream` 思绪、`capabilities` 能力清单。

**修复**：补齐 7 项，全部是**真判定**：

| 新增项 | 能抓到的真实故障 |
|---|---|
| 拦截与模板 | 模板缺核心占位符 / 占位符没被替换 → "每次都会回退默认模板，你的改动不生效" |
| 消息防抖 | 防抖开着但合并器实例缺失 → "连续消息不会被合并" |
| 润色 | **润色开启但模板为空** → "每次直接返回原回复，等于没润色" |
| 生图 | 后端选独立 API 但没配模型 → "无法生成" |
| 穿搭与衣柜 | 衣柜读取失败 / 开启但存储未初始化 |
| 思绪 | 留档读取失败；回注条数为 0 时说明"只留档、不回注" |
| 能力清单 | 注册表为空 → "模型无法主动做事" |

### 问题 2：`bg_tasks` 判定过粗（会误报）

原逻辑只看"有没有活着的后台任务"——内心模块关闭时循环本就不该启动，却报 FAIL。
改为**按配置算出应该有哪些循环**再核对，缺失时精确列名并区分"刚启动还在起"。
实测输出：`应运行的后台循环没在跑：内心循环、主动循环（插件刚启动时可能还在起，稍后重试）`。

### 问题 3：清单未加载时显示"0 项"

看起来像功能坏了。改为"清单未加载"，并在卡片内引导"点上方「一键只读测试」即可逐项体检全部模块"。

## 实测结果（真实配置 + 真实数据快照）

**23 项全部可执行；20 通过 / 3 报故障**：

| 项 | 判定 | 说明 |
|---|---|---|
| `memory_bridge` | ❌ | 「已运行，但协同桥接不可用：请确认『插件协同桥接 → 启用桥接 API』已开启」 **← 真实环境问题：记忆功能实际是断的** |

其余 20 项全部 ✅（含新增的拦截与模板、消息防抖、润色、穿搭、思绪、能力清单）。

## 我的第 4 条教训（记入手册）
用脚本做"整段替换"时**锚点不能取得太宽**：本次替换 `bg_tasks_status` 时把紧邻的 `logger_status` 一起删掉了，
运行时才报 `NameError`。**替换后必须立即可运行一次**（不能只看编译通过）。
