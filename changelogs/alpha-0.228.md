## 25 模块深度自检 · 第 16 轮：wardrobe 穿搭 —— 先修掉我自己埋的自检误报

### 问题 1：我第 2 轮加的自检项把衣柜件数算错了（0 件 vs 实际 20 件）
自检项 `wardrobe_status` 按 `data["closets"]`（**复数、字典**）统计，而真实结构是
**`data["closet"]`（单数、列表）** → 永远算出 0 件；而且它**报的是 OK**（"穿搭可用（衣柜 0 件）"）——
属于"看着正常、数字是错的"，比报 FAIL 更容易骗过人。
**修复**：改为读 `closet`（兼容 list / dict）。
**同时建立方法**：新增把自检项输出与**独立读取的真实数据逐项对照**的探针
（衣柜件数 / 表情包分类 / Token 累计 / 思绪留档），结果 4/4 一致。

### 问题 2：`set_outfit` 对字符串没有容错
误传字符串会按可迭代**逐字拆分** → `["黑","色","机","能","风","衬","衫"]`，生成一份"全是单字"的穿搭。
生产路径目前安全（面板传列表、能力层自带容错），但接口本身不设防。
**修复**：加同款容错（按 `、`/`，`/`,` 切分），三个入口行为一致。

### 验证 15/15
渲染（真实穿搭/空/None）、存储 20 件、衣柜上限 70、**换装四种情形**（列表 / 单字符串 / 分隔串 / 截断 8 件）、
解析（代码块/乱输入）、生成提示词、两处联动（生图带穿搭、日程接收 closet）。
**回归 498/498。**

### 方法论补强
从本轮起，**自检项的输出必须与真实数据交叉核对**——"能跑"不等于"数字对"。
