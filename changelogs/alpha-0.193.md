# alpha-0.193

## 用户五项反馈的修复轮

### ① 生图「控制台里显示已生成，但什么也不显示」→ 面板加图片预览

- **根因**：插件面板「生图」页的「最近生成」只渲染**文字**（时间/✅/kind/prompt/耗时），从来没有图片预览——生成结果存在但页面看不到；记录里也没存文件名（只有可能被截断的路径）。
- **修复**：
  - `image_gen`：记录新增 `name`（文件名）；新增 `preview_for(name)`（返回 `thumb` 200px / `full` 1280px 的 data URL，PIL 缩放、无 PIL 时小图兜底）、`recent_with_preview(limit)`（记录 + 缩略图）、`_image_path`（只取 basename，防目录穿越）。
  - `page_api.image_status`：最近 20 条记录附带缩略图/大图。
  - 面板「生图」页：每条记录显示 84px 缩略图（无预览时显示「无预览」占位），**点击缩略图弹出大图**（`openImagePreview`，点任意处/Esc 关闭）。
- **注**：对话里（QQ）发图一直是正常的；这一项是控制台可看性。

### ② 很久没对话，好感度不会降低 → 关系「自然降温」

- **根因**：`RelationshipStore` 只增不减，没有任何时间维度。
- **修复**：新增降温策略（锚点式，读取即结算、幂等、变化才落盘）：
  - 锚点 = 上次接触时的好感度（`affection_anchor` / `affection_anchor_at`）；免降温期内不动，超过后按 `(已过天数 - 免降温天数) × 每天幅度` 回落，有下限；**任何一次互动（或手动调整）都重置锚点**。
  - 配置（关系页）：`decay_enabled`（默认开）、`decay_free_days`（默认 3 天）、`decay_per_day`（默认 0.01）、`decay_min`（默认 0.15）。
  - 关系页人物卡新增「今天聊过 / 已 N 天未互动」显示（`idle_days`）。
  - 降温后关系阶段随之回落（好感度决定陌生/普通/熟络/亲近）。

### ③ 人格模块的「洛洛」示例 → 已删除

- 位置：人格页「一键生成人格注入体」的输入框 placeholder。原为「例如：你是洛洛，一个温柔但偶尔毒舌的学姐，来自……」→ 改为不含具体人名的中性示例（「例如：一位温柔但偶尔毒舌的学姐，说话简短、爱用反问……」）。

### ④ 表情包似乎不会被发送 → 补齐接管链路的「判定插入占位符」

- **根因（两处）**：
  1. **接管改换链路缺一环**：表情包的机制是「回复文本里含 `[EMOJI:分类标题]` 占位符 → 渲染成图片发送」，而占位符由**判定模型**插入。主链路径由 `reply_pipeline.process()` 的判定完成；**接管改换是插件直连生成、绕过判定** → 永远没有占位符 → 表情包从不发送（用户当前正是接管改换模式）。
  2. **图库实际是空的**：用户的分类「表达轻微吐槽」存在，但 `emojis/<cid>/` 里一张图都没有（上传从未成功落盘）；而前端此前**不检查上传返回值**，失败也提示「已上传」，所以看起来像上传成功了。
- **修复**：
  - 新增 `ReplyPipeline.apply_emoji_pick(event, text)`：只判「这轮要不要配表情包」（轻量 prompt `build_emoji_prompt`，输出 `{"emoji":[{"category","position"}]}`），命中则插入占位符；接管改换链路在润色后调用它。闸门：`emoji.enabled` → **只有真的有图的分类才参选**（`_usable_categories`）→ 用户 opt-out → 判定模型（`emoji_judge`，回退 `judge`）→ `send_probability`（含反馈权重抽签）。
  - 上传链路：后端校验分类存在、文件内容非空，成功/失败**都写日志**；前端检查桥返回的结构化失败（`ok:false`/`error`）并逐张报错，不再无条件提示「已上传」；分类无图时页面显式提示「这个分类还没有图片——表情包不会被发送」。
  - `emoji.send_probability` 默认值 0.25 → **0.5**（两道闸相乘才是最终频率；用户已有配置不受影响，可自行调整），hint 说明调法。
- **实机前置条件（重要）**：需要**真的往分类里上传几张图**，表情包才可能发出。

### ⑤ 每次改设置保存后页面被强制拉回顶部 → 保留滚动位置

- **根因**：`saveConfigValue` 成功后调用 `refreshCurrentView()`（各模块页整页重渲染），且 19 处「保存/应用/生成」按钮后的 `renderXxx()` 同样重建 DOM → 视口回到顶部。
- **修复**：新增 `_scrollSnapshot/_scrollRestore`（记录并恢复 window/文档/`#view` 等候选容器的滚动位置，双帧 rAF 恢复）与 `rerenderPage(pageKey, fn)`（**同页重渲染才保护**，切换选项卡仍正常回顶）；`refreshCurrentView` 与 24 处 `await renderXxx()` 调用点全部接入。
