# alpha-0.214

## 用户指出的问题（我确认属实，是设计疏忽）

> "「思绪」模块并没有占位符注入啊，而且「拦&改」也没有「思绪」相关的占位符提供。
> 而且思绪这个模块也没有清晰的功能简介啊（比如"思考内容连续化"什么的）。"

**核实结果：三点都对。**

| 用户的观察 | 实际情况 |
|---|---|
| 没有占位符注入 | `TEMPLATE_PLACEHOLDERS` 18 个占位符里**确实没有思绪**——它是在 `main.py` 里**硬编码追加到 system 尾部**的，绕过了模板体系 |
| 拦&改没有思绪占位符 | 后端下发的 chips 清单来自 `TEMPLATE_ORDER`，里面也没有 |
| 没有功能简介 | 思绪页只有开关/统计/留档/设置，**没说这是干什么用的** |

**为什么会这样**：0.204 做「思绪（内心持久化）」时，为了少动模板引擎，直接把它追加到提示词末尾——
功能是通的（面板留档里现在有 12 条真实记录），但**用户看不到、也控制不了它**，与其它模块（人格/关系/风格/状态/日程/记忆…）的机制不一致。这是设计上的偷懒，不是"迭代了什么"的问题——是我漏了把它接进占位符体系。

## 修复

### 1. 新增 `{思绪}` 占位符（进入模板体系）

- `TEMPLATE_PLACEHOLDERS["inner"] = "{思绪}"`，顺序排在 `{状态}` 之后（状态 → 思绪 → 日程）
- 后端下发给前端的 chips 清单（`placeholder_list()`）自动带上它 → **「拦&改」里现在能看到并点击插入**
- 两个默认模板（当前默认 + 旧版默认）都加上 `{思绪}`
- **两条接管链路都支持**：`_takeover_reply`（直连）与 `_takeover_via_mainchain`（走主链）
  —— 后者此前**根本没有思绪注入**，现在也有了

### 2. 兼容：模板里没写 `{思绪}` 也不会丢功能

用户已保存的模板不含 `{思绪}` → 插件检测到后**仍然追加到提示词末尾**（与旧行为一致），
只是"位置由插件决定"；一旦用户在模板里写上 `{思绪}`，位置就完全由他决定。
（测试覆盖：含占位符按位置注入 / 不含则末尾追加且**只注入一次** / 关闭模块则两条路都不注入）

### 3. 面板功能简介（你指出的第三点）

思绪页顶部新增一张说明卡：

> **这个模块是做什么的** · 思考内容连续化
> 每一轮回复时，它会另外写下**一句没说出口的心里话**——对方看不到，但会留档在这里；
> 下一轮再把这句话交回给它，让它接着往下想。这样它的在意、疑惑、忍住没说出口的话会像一条线延续下去，
> 而不是每轮都从零开始。
> 注入位置由「拦＆改」模板里的 `{思绪}` 占位符决定（模板里没写时会自动追加到提示词末尾，功能不受影响）。

另外：模块列表里的描述也从"没说出口的那半句：留档、回注与开关"改成
"**思考内容连续化**：每轮藏起半句没说出口的心里话，下一轮接着想（{思绪} 占位符）"；
「拦＆改」页新增该占位符的说明卡。

## 我这次的教训（记在手册里）

1. **改后端多文件时，每改一个都要单独编译**——这次我用脚本往 `intercept.py` 插 `{思绪}` 时，
   PowerShell 的 here-string 吞掉了引号，写进去的是 `    {思绪}\n`（没有引号）→ **语法错误**。
   我只编译了 `main.py` 就以为没事，直到运行时报错才发现。
2. **前端改动必须以截图为准**——我第一次只改了润色页那份 chips 常量，截图才发现「拦&改」用的是
   **后端下发**的清单（另一条通路），差点又交了个"改了但看不到"的结果。
3. **PowerShell here-string 里写带引号的 Python 会出事**——已经踩了三次，一律改用脚本文件。
