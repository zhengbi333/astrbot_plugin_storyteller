## 表情包模块重设计（你定夺：LLM 判定 + 概率 + 学习/去重/可关 + 三栏页）

- **发送机制**（回答「需要 LLM 判断吗」——需要，判定模型就是 pipeline.provider_id，负责"这个语境该不该发表情"）：
  - 判定模型（沉默/草草回复/表情包/正常发送）→ **概率闸**（send_probability 默认 0.25，像人十句配一张）→ **同图去重**（duplicate_days 默认 3 天：同一张图 N 天内不重复，渲染时记录）→ **反馈学习**（用户对刚发表情包回应正面/负面词 → 该分类权重 ±1（封顶 ±6），概率按 0.5~1.5× 微调）→ **opt-out**（用户明说「别发表情包」自动停用、说「可以发表情」恢复——仅显式表达生效）。
  - 示意图：回复 ⊃ 判定 LLM ⊃ [EMOJI:分类] ⊃ 概率闸（×反馈权重）⊃ 渲染（去重）⊃ 发送。
- **页面三栏**：左=图库与分类（上传/编辑/删除）；中=发送记录 + 反馈学习记录；右=发送设置（概率/去重天数/判定模型/抢话裁决模型）+ 分段回复**提示卡**（AstrBot 自带分段回复，插件不重复实现，避免冲突——引导用户到平台设置开启）。

## 「发送」页：缓冲 + 被抢话裁决（你定夺：完整变现 + 绑定接管生成）

- **承载**：仅「接管改换」链路（我们生成我们发；放行/走主链由 AstrBot 管线发送无法缓存——页面已说明）。
- **缓存**：回复按自然句段拆独立缓存（每句一条，长句夹断、超短尾句并入），后台逐条发送，间隔按字数节奏（0.8~4s 可配，像打字停顿）；每条发送成功回填记忆时间线（role=bot）。
- **抢话**：发送期间用户新消息 → 裁决（send.interrupt_judge_enabled，模型 send.interrupt_judge_provider_id 留空回退判定链）：
  - **A**：提速发完剩余缓存，新消息正常一轮（像话没说完先说完再回应）；
  - **B**：丢弃剩余，把「没说完的话」注入本轮生成上下文（`（你上一段话还没说完就被对方打断了——还没说完的是：…）`），像被打断后重新组织语言。
  - 关闭裁决固定 A；裁决失败兜底 A。
- **页面三栏**：待发送队列（每条√已发/未发 + 清空）｜裁决与发送记录｜发送设置。
- 已知边界：插件重载未发完的缓存丢弃（像话说一半被打断，不落盘）；与 AstrBot 分段回复潜在双段——建议二选一（提示卡已说明）。
