# alpha-0.273

## 先查证：默认安全其实已经成立

我原以为要「把白名单默认改空」，但查证后发现：

```
capabilities.astrbot_tools_enabled   默认 false   ← 总开关默认关
capabilities.astrbot_tools_allowlist 默认 ""      ← 但那时的语义是「全给」
```

**总开关默认关，所以新装本来就不给任何工具。** 你已经手动开了，那是你的选择，不该动。

## 真正的隐患在 hint 文本里

```
"留空表示允许全部已激活工具"
```

谁清空白名单，就等于把**全部工具**放给所有能跟她说话的人。这是隐性危险，不是显性的。

## 改法（配置化，不破坏老行为）

新增 `capabilities.astrbot_tools_empty_means`：

| 值 | 含义 |
|---|---|
| `all`（**默认**） | 留空 = 给全部（历史行为，不动） |
| `none` | 留空 = **一个都不给**（更安全） |

- 白名单**非空**时，两种模式行为完全一致（只给名单里的）；
- 改 hint，把「留空意味着什么」写清楚，不再藏在代码里；
- 用哨兵 `{"__none__"}` 实现「一个都不给」，bundle 的白名单过滤会自然把全部挡掉，**没有新增分支**。

## 验证（`audit_89_default_safety.py` 10/10）

- **A**：总开关默认 `false`；未开时工具集为空；
- **B**：`empty_means` 默认 `all`（不破坏）；留空+all→给全部；留空+none→一个都不给；
- **C**：白名单非空时，`none` 模式下仍只给名单里的；
- **D**：**与 P0-1 不冲突** —— 群聊仍然挡写工具、保留只读。
