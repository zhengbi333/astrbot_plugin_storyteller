# alpha-0.267

## 现象

点某些页签，界面停在「加载沉默…」「加载防抖…」这类文字上，**一直不动**。

## 根因：超时设成了 150 / 180 秒

```js
const result = await withTimeout(bridge.apiGet(endpoint, params || {}), 150000, ...)
const result = await withTimeout(bridge.apiPost(endpoint, body || {}), 180000, ...)
```

`150000` 毫秒 = **150 秒**。某个接口一旦挂住（后端慢、或返回了不该返回的东西），
页面就会**卡满 150 秒**才报超时。你看到的就是「一直在加载」。

## 修了两处

| 位置 | 改前 | 改后 |
|---|---|---|
| `apiGet` | 150 秒 | **8 秒** |
| `apiPost` | 180 秒 | **8 秒** |

8 秒后如果还没回，会抛 `超时（8 秒无响应），已终止等待`，
页面显示「加载失败：…」而不是永远转圈。

## 顺带修掉一个我自己埋的雷

0.265 我加的「渲染序号过期就重渲染当前页」有死循环风险：
递归调用会再次递增序号，快速连点时可能无限递归。

现在改成：**只记日志 + 清掉残留的「加载中…」占位**，提示「已切换到其它页签，请重新点一次」，
**不再递归**。

## 为什么会出现「某些页签」特别容易卡

- 沉默页、防抖页会做**实时轮询**（`stopAllPolling` 只在切页时调），
  轮询和首次加载叠在一起时更容易撞上慢接口；
- 判定页要读 `judge/stats`（涉及 7 个判定器的 provider 解析），本身比纯静态页重；
- 守则页要读 `acting/sections`（读 9 个 `.md` 文件）。

8 秒超时对这三个都是够的；如果实测仍不够，会看到明确的「超时」提示，而不是假死。

- `node --check app.js` 通过；
- 一键验收 49 项；
- 代码自检：`150000` / `180000` 均已为 0 处。
