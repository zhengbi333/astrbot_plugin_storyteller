# alpha-0.247

## 一、补上「上下文预算」（记忆插件替代不了它）

之前只有工具结果压缩，**对话消息本身从来没被处理**：`req.contexts` 一路增长，
而 system 静态部分已接近 2900 字（模板 253 + 记忆注入 1600 + 扮演守则 900 + 任务守则 160），
长对话必然超窗；超窗后模型最先丢的恰恰是近期内容。

新增 `context_budget.py`：

- 估算 `system + contexts + prompt` 总字数；
- **没超预算 → 一个字都不动**（默认路径）；
- 超了 → 保留最近若干条原文，更早的每条取前 80 字合成**一条** `system` 摘要（标注已压缩）；
- 还超 → 逐步缩小保留条数（最少 4 条），最后连摘要也截断；
- 不改写内容、不动角色、不删当前用户消息；失败只记 debug，不影响回复。

配置：`context.max_chars`（默认 14000）、`context.keep_recent`（默认 8）。

> 和记忆插件的分工：记忆是「往 prompt 里加」（跨会话检索注入），
> 预算是「从历史里减」（本次对话窗口）。只有记忆没有预算，长对话照样爆；
> 只有预算没有记忆，跨会话就断层。两件都得有。

## 二、认知做完了事 → 自动结算相关约定

之前：她答应做 PPT → 认知真的做了、发了、写了记忆 → 但**约定仍挂着未结算**，
下次还拿它当由头（因为原来的结算只看对话文本有没有说「做好了」）。

现在：认知回传完成类动作（`doc_write / doc_export / send_file / learn / download`）时，
人格把行动文本与未结算约定做**字符二元组匹配**（至少命中 2 个不同片段才算相关，
避免「做文档」这种泛词误伤），命中就 `mark_promise_settled`，并把条数回传给认知的 `settled` 字段。

## 四、已知边界

- 预算按字数估算，不是精确 token 数（不同模型分词不同）；
- 压缩摘要只留每条前 80 字，细节会丢 —— 这是省窗口的代价；
- 约定匹配是启发式（二元组），极短或高度泛化的约定可能匹配不上（宁可不结算，也不误结算）。
