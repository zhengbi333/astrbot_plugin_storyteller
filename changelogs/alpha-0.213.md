# alpha-0.213

## 第 10 轮迭代（收官）：只读能力并发执行

### 诊断

工具循环原来是这样写的：

```python
for index, call in enumerate(calls):
    result = await cap_dispatch(self, event, cap_name_from_tool(name), payload)
```

——模型一轮里同时要"查资料 + 翻留档"时，只能一条一条等，等于多花一次往返（每次 0.8~1.5s）。

**但不能全部并发**：写类能力并发会有竞态（两个能力同时改同一个文件时，后写的会覆盖先写的）。

### 修复

给 `Capability` 加一个 `readonly` 标记，只让**查/翻类**能力并发：

| 只读（可并发） | 写类（保持串行） |
|---|---|
| `memory_recall`（回忆）· `web_lookup`（联网查）· `history_lookup`（翻历史）· `inner_recall`（回想思绪） | `memory_write` · `manage_todo` · `emoji_send` · `photo_take` · `schedule_edit` · `outfit_change` · `mood_note` · `share_inner` · `proactive_schedule` |

实现要点：
- 先把这一轮的 `tool_calls` **分拣**：校验不过的（超额 / 未提供 / 参数坏）照旧给拒绝结果、不执行；
  其余按只读 / 写类分组。
- 只读**≥2 个**时才并发（1 个并发没有意义，行为与原来一致）；写类逐条 `await`。
- 结果按 **calls 原始顺序**汇总回填（回填顺序是协议要求），标记也照原顺序去重。
- 并发里任何一个抛异常都只影响它自己（其它照常，异常转成失败的执行结果）。
- 开关 `capabilities.parallel_readonly`（默认开）；关掉即完全回到"逐条执行"。
