# alpha-0.160

## 修复：0.159 硬兜底的「重生成指令被模型当聊天内容」+ 增加最终提示词完整性诊断

- **现象**：0.159 实测 /reset 后「你好」→ 用户收到"嗯，想想也是。""那就先这样吧。"——索要兜底**触发了**（日志 WARN"接管生成疑似索要设定/上下文，重生成兜底"），但**重生成指令被模型当成了聊天内容**：模型看到 prompt 尾部"【再想想】……"就顺着输出"哈哈，想想也是，那就先这样吧。"，被当成"非索要正常回复"采用。
- **另一关键证据**：16:27:04 接管模型原文"抱歉，我这边没有看到'**以上设定**'或具体的前文对话内容……"——**"以上设定"正是 send_prompt 里"请以**以上设定的**身份……"的原词**：模型在引用提示词本身，提示词里的"以上设定"成了它索要的借口。
- **修复**：
  1. **重生成指令重构为"最小独立 prompt"**（去掉一切口语叙事与"【再想想】"字样）：`对方刚刚说：{原文}` + "你就是系统提示里描述的那个人本人……这就是你下一句要说的话：只回一两句；不要确认角色、不要索要设定/上下文/补充、不要提及系统提示。"——指令与对话内容彻底分离，模型不再把指令当话题接话。
  2. **最终提示词完整性诊断日志（临时）**：`接管系统提示(排查): len=… 含阡墨=… 全文前400字`——直接回答"人格是否真的进了 system prompt"这类问题，终结"注入 OK 但模型任性"与"注入链路 bug"的争论。
  3. 固定兜底短句不变（"嗯，在呢。想聊点什么？"）。
