# alpha-0.217

## 25 模块深度自检 · 第 3 轮：models 模型

模型链路是**全部生成功能的依赖根**——任何一个功能解析不到模型，就等于该功能静默失效。

### 执行链核实

`resolve_chat_provider(context, config, function)`（models.py:124）三段式：
1. 读该功能的配置键（`FUNCTION_KEYS`，**22 个功能**各自映射；13 个旧键兼容读取）→ 有值就查注册表，
   查不到 → **报错驳回**（不静默换别的模型）
2. 模块内留空 → 走「留空回退模型」；回退为空或无效 → 驳回
3. 「留空回退模型」已关闭 → 直接驳回

`resolve_embedding_provider` 是**严格模式**：嵌入模型不参与回退（类型不匹配）。

**模型页**（`renderModels`）= 回退模型卡 + 三栏分组列出各模块的模型字段；`field(m, k)` 与各模块页
**共用同一份配置变量**（`bindSettingsIn` 统一保存）→ 页面底部"改哪边都同步生效"的说法**准确**。

### 修复：留空字段看不出"实际用哪个模型"

模型页字段空着时，用户无法判断这个功能到底能不能用。现按**三种状态**分别提示：

| 状态 | 提示 |
|---|---|
| 「留空回退模型」已关闭 | 「留空回退模型」已关闭 → 这个功能没配模型时，调用会被驳回 |
| 回退模型本身也没设置 | 回退模型本身也没设置 → 这个功能的调用会被驳回 |
| 有可用回退 | 未配置 → 实际走回退模型 **X**（灰字） |

> 第一版我把后两种合并成一句"未配置且没有可用回退"，与字段自带的「按留空回退模型策略」说明**语义打架**——
