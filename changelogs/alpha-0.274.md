# alpha-0.274

## 现状：心情只影响"说什么"，不影响"做什么"

以前心情（调子/转速/电量）只被翻译成文字塞进 system：
「调子轻快」「转速慢」。**她说话的措辞会变，但行为节奏一点不变** ——
表情该发多少还是多少，回复该等多久还是多久，主动搭话该多克制还是多克制。

Aurabot 那边心情是**真的会改行为**的。这一轮补上。

## 三处接入

| 行为 | 原值 | 现在 |
|---|---|---|
| 表情包概率 | `emoji.send_probability`（0.5） | × f(电量)：电量满 → 更爱发；电量低 → 不爱发 |
| 回复间隔 | `send.chunk_interval_min/max` | × f(转速)：转速急 → 间隔变短（回得快）；转速慢 → 拖一点 |
| 主动搭话冷却 | `proactive.cooldown_after_chat_minutes`（30 分） | × f(调子)：调子轻快 → 冷却短（更愿意凑上来）；低沉 → 更久 |

## 换算函数放在 `presence.py`（不新建模块）

```python
mood_factor(presence, dim="tempo", strength=0.5, direction=-1)
```

- `tone` / `tempo` 是 **-1..1**（0 中性）；
- `battery` 是 **0..1**（0.5 中性）；
- `direction=1` 同向、`-1` 反向（转速高要缩短间隔，所以用 -1）；
- 结果夹在 **0.15 ~ 2.5**，避免把间隔压到 0 或放大到离谱。

**`presence.py` 本来就管这三张表**，把换算放在这里符合我们的模块划分，没有为了改一件事就新开文件。

## 全部可配（不写死）

新增 `mood` 配置组：

| 项 | 默认 | 说明 |
|---|---|---|
| `effect_enabled` | true | 总开关，关掉就回到"只影响措辞" |
| `effect_emoji` | 0.5 | 电量 → 表情频率的强度 |
| `effect_pace` | 0.5 | 转速 → 回复快慢的强度 |
| `effect_proactive` | 0.5 | 调子 → 主动搭话的强度 |

强度 0 = 完全不影响，1 = 最多差 2 倍。**默认 0.5 是温和的**，不会让你觉得她忽冷忽热。

## 测试抓到一个真 bug

`mood_factor` 最初写的是：

```python
raw = float(presence.get("battery", 0.5) or 0.5)
```

**电量 0（耗尽）是合法值，但 `0 or 0.5` 会变成 0.5** ——
"她累到没电了"被当成"电满"。测试 A8 抓到了，已改成显式判 `None`。

## 验证（`audit_90_mood_effect.py` 25/25）

- **A** 数学：三个维度的中性值、极值、方向（同向/反向）各 8 条；
- **B** 强度与边界：strength=0 → 恒 1.0；strength=1 → 2.0；上下限保护；畸形输入不炸；
- **C** 三处都接上（表情 2 处调用、间隔、主动）+ 三个 helper 都有定义；
- **D** 总开关能完全关掉：关闭时倍率恒 1.0；打开时转速满 → 倍率 < 1（回得快）；
- **E** schema 四项都在且都带 hint。

## 已知边界

- 表情概率的**下限**被夹在 0，所以电量极低时只是"很少发"，不是"绝对不发"；
- 主动搭话只调整了**冷却**，没动 `max_daily`（每日上限仍是你配的值）；
- 这些是**概率性**影响，单条消息看不出来，要连续聊十几条才有体感。
