# alpha-0.54

- **判定彻底重写为宽度无关**（修复 0.53 的"判定框漂移"问题）：
  - 根因：0.53 用「被拖卡片右缘 = 中心 + 自己宽度的一半」对「目标中心 = 目标左缘 + 目标宽度的一半」——选项卡宽度各不相同（2 字窄卡 / 表情包 3 字 / Token 英文），导致不同卡片、不同位置的触发点漂移（有的正好、有的偏一个卡片）；
  - 现在：判定基准 = **被拖卡片中心**（永不漂移）；让位触发 = **卡片中心进入目标卡片的实际范围**（用目标真实左/右缘，不依赖任何"半格"计算）——任何宽度组合下，触发时都正好盖住目标约一半，左右对称；
  - 让位区间含目标自身、左右对称；落位仍为中心比较（顺序判定不变，拖过一半才换位）；
- 模拟操作测试升级为**宽度参差布局**（identity 宽 96 / emoji 宽 104 / token 宽 72 / 其余 80），29 项全过；并做了回归注入验证（0.53 右缘公式 → 4 项 FAIL，确认测试能捕获宽度漂移）。
