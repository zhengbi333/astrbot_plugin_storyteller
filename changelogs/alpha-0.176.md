# alpha-0.176

## 修复①：流式聚合误删「前缀小块增量」——所有 JSON 生成任务解析失败（根因实证）

- **用户反馈（正确）**："所有生成解析 json 类型的任务都失败了，无法解析"——日程/状态/衣柜/画像/主动等全部中招（日志：日程生成重试一次后仍失败，原文 `{"entries": [start": "00:00"...`，每个对象开头丢 `{"`）。
- **根因（证据链完整，含实测）**：
  - 排查：读到返回原文规律 100% 一致——**每个 JSON 对象开头的 `{"` 都丢失**（`[start": "00:00"`）；
  - 实证复现：用部署环境真实端点（DeepSeek 官方 `https://api.deepseek.com/v1` + `deepseek-v4-flash-vision-exp`）抓原始流——**模型输出完全正常**：按 1~8 字符增量逐片输出，且**每个对象开头的 `{"` 是独立分片**；
  - 元凶：`models.py` 的「快照去重」逻辑（直连 `_direct_stream` 与原通道 `_collect_stream` 两处同款）——
    `if js and ts and (ts.startswith(js) or js.startswith(ts)): 保留更长者`——**当新增量恰好是已拼文本的前缀（`{"` 必然是 `{"entries": [` 的前缀）时，被误判为「重复快照」直接丢弃**；
  - 旧逻辑在新模型/渠道（0.175 后才配置 `deepseek-v4-flash-vision-exp` 全模块模型）上**首次实战**触发：此前模拟器测试的 chunk 较小/大而整，从未出现「2 字符且为整体前缀」的增量，20/20 全绿因此未捕获。
- **修复（两处统一）**：判定改为——
  - `ts == js`（完全重复块）→ 忽略；
  - `len(ts) > len(js) and ts.startswith(js)`（更长的整段快照）→ 替换为新全量；
  - **其余一律追加**（包括恰好为已拼文本前缀的短增量）。
- **验证（真实流重放对比）**：旧逻辑复现 `{"entries": [start": "09:00"...`（解析失败，与生产日志完全一致）；新逻辑得到完整 `{"entries": [{"start": "09:00"...`（解析成功，entries 3 条）。

## 修复②：主动消息发送失败「适配器未连接」——平台前缀诊断 + 单平台自动回退

- **用户反馈**：主动对话可预览但不发，提示"适配器未连接"，实际适配器已连接（朋友环境，本机未复现）。
- **根因分析（读 AstrBot 4.27.5 源码确认）**：`context.send_message(session)` 用 UMO 字符串 `platform_name`（=适配器 `meta().id`）匹配 `platform_manager.platform_insts`；匹配不到即 warning + 返回 False。**只要 `proactive.session_platform`（默认 `aiocqhttp`）与实际已连接适配器 ID 不一致（Telethon 用 `telethon`、QQ 官方 API 用 `qq_official` 等），或用户填了带包装前缀的会话，就会报"适配器未连接"**。
- **修复**：
  - `_resolve_session`：Message 节大小写归一（FriendMessage/friendmessage 均可）、剥离 `message:/msg:` 等最外层包装前缀；
  - 发送失败诊断：`_send` 失败时枚举 `context.platform_manager.platform_insts` 输出"已连接平台列表"，明确提示"配置前缀 X 未匹配（已连接: …）"；
  - **单平台自动回退**：配置前缀不在已连接平台、且 AstrBot 恰好只有一个平台时，自动用该平台重试一次（唯一适配器，无错发可能）；
  - 主动页「消息平台前缀」由手填改为**已连接适配器下拉**（数据源 `proactive/status.connected_platforms`；无适配器时回退原输入框）。

- **修复**：
  - `detect_image_intent`：触发词新增 **「拍」** 与动物量词（只/条/头/朵/座）、画面对象词扩展（自拍/写真/人像/合照/立绘/风景/表情）；新增**聊天暗示负向**（发我/发你/发来看看/发一张…）——"拍个照发我"仍不拦截为生图；"拍一张自拍""帮我画只猫""给我来张头像"等自然说法均可命中；
